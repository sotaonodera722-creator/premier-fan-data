## 1. 何を作っているか

**https://premier-fan-data.vercel.app/**

プレミアリーグの順位表・全20クラブ・全選手・全380試合を日本語で見せる個人サイト。

> 日曜の朝に10分開けば、週末に何が起きたか・日本人選手がどう関わったか・今夜どの試合を観るべきかが、
> すべて日本語でわかるサイト。速報サイトでもデータベースでもなく、**週に一度開く習慣の場所**。

### 中心の問い

**「その日本人選手はレギュラーなのか」**

出場時間・チーム内序列（同ポジションのチームメイトと比べて何番手か）・
4状態分類（不動 / ローテーション / 出番待ち / 欠場）。

### 読者は4層

| 層 | 誰か | 詰まるところ |
|---|---|---|
| **A** 日本人選手だけを追う人 | 三笘・遠藤の名前で検索して来る | クラブの区別がつかない。順位表の数字が意味に変換されない |
| **B** サッカーは好きだがプレミアは追えていない | W杯は観る。知っているクラブは5つ程度 | 今シーズン何が起きているかの文脈がない |
| **C** かつて観ていたが離れた | ファーガソン／ヴェンゲル時代を知っている | 浦島太郎状態。Hull City が上位にいる意味がわからない |
| **D** 今も観ている | 深夜に起きて観る層 | **主客ではない。**速報性でも分析の深さでも他に劣る |

**狙いは A → B → C の変換。**

### サイトが担う3つの役割

- **翻訳機** — 英語のプレミア世界を日本語にする。順位表の数字を「意味」に変換することを含む
- **文脈供給機** — 「Hull City が2位」がなぜ驚きなのかを説明できる状態にする
- **定点観測の場所** — 週に一度開く習慣。4時間更新では速報に勝てない以上、勝てるのはリズムの設計だけ

### 構造的な発見: 日曜の朝は節の途中

第3節を日本時間に直すと 土04:00 → 土20:30〜23:00（5試合）→ 日01:30 → 日22:00 → 月00:30。
**日曜の朝に開く瞬間は、構造的に節が終わっていない。**
「週末のまとめ」ではなく**「追いつきながら、今夜観る試合を選ぶ」場面**。

## 4. Vercel のデプロイ容量 — 設計を縛る構造的事実

**無料枠のデプロイメントストレージだけが上限を超えた**（10.26 GB / 10 GB）。
他のメーター（CPU・関数・帯域）は1%未満。

Vercel はデプロイ1本ごとに事前生成ページを丸ごと保管する。当時1本214MB、
うち**まだ1試合も行われていない350試合のページが85.2MB（40%）**。1日6本デプロイで**1日1.3GB増**。

**決めたこと**: 事前生成を**シーズンを通して件数が変わらない集合**に限る。
直前＋進行中の節（20試合）と、日本人選手9人＋ランキング上位（37人）。
959ページ → 88ページ、214MB → 約30MB。

**「消化済みの試合だけ」では駄目だった** — 5月に380件になり元に戻る。

### 覚えておくべき副作用と落とし穴

- **`npm run build` が「全ページが落ちないことの証明」でなくなった。**871ページに網がかからない。`npm run smoke` が標本で埋めている
- **保持ポリシーはリポジトリに現れない**（Settings → Build and Deployment）。2026-09-10 に本番1週間・プレビュー1週間・失敗1日に設定済み
- **保持ポリシーでは直近20本のプレビューは消えない。**期限を過ぎても残る。`vercel remove` にデプロイID（`dpl_...`）を渡して1本ずつ消すしかない。**プロジェクト名を渡すと現在の本番まで消える**
- **削除しても容量はすぐ空かない。**「最近削除されたデプロイメント」に30日残る。使用量は GB-月で数えるため、既に積まれた分はその期間下がらない
- `vercel.json` の `ignoreCommand` で docs のみの変更はビルドしない。**`git diff HEAD^ HEAD` は使わない**（1 push 複数コミットで取りこぼす）。判定できないときは必ずビルドする側に倒す

**今後ページを増やすときの判断基準**: 新しい動的ルートを作るときは、
**事前生成する集合が件数で上限を持つか**を先に決める。「全部」と書いた瞬間に太る。

## 5. 進め方 — 誰が何を決めるか

役を分けている理由は分業ではなく、**作った本人に判定させないため**。

| 役 | 誰 | 決めてよいこと |
|---|---|---|
| **代表** | ユーザー | 何を作るか、作らないか、優先順位 |
| **マネージャー** | セッション本体 | 実装の手順、技術的な選択 |
| **設計** | `sprint-designer` | 契約の中身（範囲の判断は代表に上げる） |
| **採点** | `qa-reviewer` | 合否（ブラウザで見えるもの） |
| **検算** | `data-auditor` | 合否（数字そのもの） |

**採点と検算は同格。どちらか一方でも不合格なら不合格。平均で救済しない。**
**間違った数字はブラウザ上で完璧に見える。**これが役を2つに分けている理由。

### 承認は2点だけ

① 契約（`docs/sprints/S◯◯.md`）の承認 → 実装 → ② 検査と最終判定。
途中の細かい判断は代表に聞かない。

### ゲート（検査に出す前に必ず通す）

```bash
npm run lint && npm run build && npm run audit
```

### 「保留（ターン上限）」は合格ではない

検査エージェントには上限がある（`qa-reviewer` 20 / `data-auditor` 15）。
保留が返ったら**確認できていない項目だけ**を渡して再起動する。確認済みは二度と見せない。

### 検査後に飛ばしてはいけない3つ

1. `docs/qa-log.md` に追記
2. 再発防止リスト（R番号）に足す
3. 持ち越しを次の契約候補として `docs/sprints/` に残す

### 6-1. 「レギュラーなのか」に検索需要はあるか → **ある。ただし言葉が違う**

Googleサジェストは一定の検索量がある語しか返さない。9選手で総当たりした結果。

- **「序列」**: 遠藤航 / 田中碧
- **「干された・構想外」**: 田中碧 干された・干された理由・構想外 / 遠藤航 構想外・戦力外・補欠・放出・別メニュー
- **「なぜ出ない」**: 三笘薫 なぜ出ない・なぜ出れない・出れない理由・なぜスタメンじゃない / 遠藤航 出番なし / 田中碧 試合出てない

- **「ポジション争い・スタメン争い」**: 冨安健洋 / 田中碧 / 遠藤航

**1件も出なかった**

> **「何番手」— 9人全員でゼロ。**

### 6-4. 市場規模

**笹川スポーツ財団「スポーツライフ・データ2024」**（全国18歳以上3,000人・300地点、2024年6〜7月調査）

| 項目 | 率 |
|---|---|
| **海外プロサッカーをインターネットで観戦** | **3.6%**（男性6.6% / 女性0.7%） |
| サッカー日本代表戦をインターネットで観戦 | 4.1% |
| Jリーグをインターネットで観戦 | 3.0% |
| サッカー日本代表戦をテレビで観戦 | 36.4% |

**概算（推定・信頼度 中）**: 18歳以上人口 約1億人 × 3.6% ≒ **約360万人**。
これが欧州サッカーをネットで観る人の**外枠**。プレミアに限ればさらに内数。
（設問定義（過去1年か常習か）が未確認のため、「毎節観る層」はこれより大幅に少ない）

**テレビの日本代表戦36.4% と ネットの海外サッカー3.6% の間にある10倍の断層**が、
A→B→C変換の実際の坂。

**U-NEXT**: 有料会員500万人突破（2025年11月、日本企業初）。ただし**サービス全体**であり
サッカーパック契約者数ではない。**サッカーパック単体の数字は非公表で、外部から確定できない。**

### 6-6. football-wire（最重要の競合）

HTML・sitemap・robots.txt を直接読んだ結果。**推測ではない。**

- **個人運営**（フッターに明記）。運営者は X **@tttkhs** と LinkedIn を公開

- **データ源は API-Football（api-sports.io）**。`/stats/about` に明記。評点もキーパスもこれ。
  **無料枠（1日100リクエスト）があり有料も月20ドル前後。入手できないデータではない**

- **`news-sitemap.xml` を別途設置**（Googleニュース枠狙い）
- **robots.txt で GPTBot / ClaudeBot / PerplexityBot / CCBot / Google-Extended を明示的に Allow**（AI検索の引用狙い）

## 10. やらないこと（判断を蒸し返さない）

- **リアルタイム速報・ライブスコア** — 4時間更新。速報を装えば古いスコアで信頼を失う

- **PC向けレイアウトの作り込み** — 壊れないことは保証するが最適化しない
- **ユーザーアカウント・通知・コメント**

> この禁止に当たらない、という整理が既にある。
