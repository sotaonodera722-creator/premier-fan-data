## 2026-09-10 — CI が落ちた: 誕生日当日の選手で年齢検査が誤検出

S14 の PR で CI の `npm run audit` が **不合格1件**で落ちた。ローカルでは通っていた。

### 何が起きていたか

CI は PR のマージ結果（自分のブランチ ＋ main）で走る。main には4時間ごとの自動更新が
2本入っていて、`lastUpdated` が 2026-09-09T20:13Z に進んでいた。この組み合わせで、

```
[不合格] 年齢が生年月日と整合する（取得時点で±1歳）
    Ao Tanaka: age=27 / 生年月日 1998-09-10
```

**田中碧の誕生日が 2026-09-10 で、その当日だった。**

検査は経過ミリ秒を 365.2425 日で割って年齢を出していた。誕生日直前のこの時刻では
10,227日 ÷ 365.2425 = **28.0006 歳**になり、保存値 27 との差が **1.0006** で許容（±1）を
わずかに超える。**暦の上では27歳のままなので、データは正しく、検査式のほうが誤っていた。**

### 直し方

`ageAt(dateOfBirth, at)` を追加し、年・月・日を比較する暦の計算に変えた
（`scripts/audit/invariants.ts`）。「生年月日がありえない選手」の判定も同じ関数に寄せた。
main のデータ・ブランチのデータの両方で 156件・不合格0 を確認。

### なぜ気づけなかったか

**ローカルでは通っていた。** ブランチのデータが古い `lastUpdated` を持っていたためで、
CI がマージ結果で走ることが差を生んだ。時刻に依存する検査は、
**手元で通ることが通ることの証拠にならない。**

R13 として登録。同じ割り算は他にもありうるので、経過年数を扱うコードは暦で数える。

### 派生する持ち越し

自動更新は main に直接 push され、audit は push の**後**に走る設計（壊れた不変条件は
たいてい提供元の事実で、更新を止めると先週のスコアを見せることになるため）。
つまり **main が赤いまま数時間放置されうる。**今回もそうだった可能性が高い。
通知の仕組みが無いので、赤に気づく手段を決める必要がある
