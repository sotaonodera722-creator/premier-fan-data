## 5. 設計上の判断

- **用語解説は語の隣に置き、出現箇所すべてに置く。** 用語集ページに飛ばすと戻ってこない。
  「初出の画面だけ」も採らない — 読者は入口を選ばず、`/teams/rankings` から入る人にとっては
  そこが初出になる。xG を5か所すべてで開けることを条件8にしたのはこのため
- **用語の選定基準は「サイトに出ていて、日本語だけでは解けない語」。** 仕様書が挙げた7語のうち
  xA・クリーンシート・H2H は**サイトが一度も使っていない**（節0で全文検索した）。
  代わりに「不動／ローテーション／出番待ち」を最優先に入れた。これはサイトが独自に定義した語で、
  外部のどこにも説明が存在せず、S09 の中心的な答え（その選手はレギュラーなのか）そのものである
- **圏の説明は増やさず再利用する。** S03 の `ZONE_MEANINGS` を基本ルール欄からも読む。
  同じ概念に2つ目の文言を書くと、片方だけが更新される事故が確定する
- **カタカナは手入力のみ。** 機械音写は誤りを量産し、誤った人名は数字の誤りより信用を落とす
- **カタカナの単位は「出場時間の上位N人」にしない。** 上位100人で出場時間の45.8%を覆えるが、
  この切り方は全画面を横断して切るので、どの画面も半分だけ日本語という最悪の見え方になる。
  切るなら**画面の単位**で切る（節7-1）
- **カタカナは表示幅を増やす。** ラテン文字は約0.5em/字、カタカナは1em/字なので、
  `Victor Nilsson-Lindelöf`（23字≒138px @12px）を「ヴィクター・ニルソン＝リンデロフ」にすると
  約190pxになる。`PlayersExplorer.tsx` のコード注釈が既に同じ問題を記録している
  （「375pxでカード内に132px、名前に使えるのは68px。Brentford は入るが ブレントフォード は入らない」）。
  **カタカナ化は R9 を確実に踏む変更**であり、条件11で対象箇所を名指しした
- **検索は「表示名」ではなく照合キーの集合に対して行う。** 選手ごとに
  ［ラテン文字名・漢字・カタカナ］を別名として持ち、クエリ側は小文字化・アクセント除去・
  ひらがな→カタカナ変換・全角半角統一を掛けてから照合する。アクセント除去は提供元自身が
  `Daniel Muñoz` と `D. Munoz` を混在させている実データが根拠
- **ランキングの同順位は順位表と同じ共有順位にする。** 1つのサイトに2つの順位規約があってはならない。
  `position`（同着共有）が読者の目に入る値であることは [qa-log.md](../qa-log.md) の R8 で確定している
- **色は使わない。** 用語解説のトリガーは点線の下線と既存の `border` / `muted` 系で表す。
  `--info` は意味論的用途のための変数であり、「説明がある」印は装飾なので使わない

## 7. 代表が決めたこと（2026-09-09 承認）

1. **カタカナ化の対象集合は 438人**（試合ページに名前が出る全員）。設計者の推奨どおり。
   367人（出場時間1分以上）で切ると、ベンチに入っただけの71人が試合ページでラテン文字のまま残り、
   同じベンチの並びが半分ずつ違う文字種になるため。対象外の110人は試合ページに一度も名前が出ない。

2. **出場時間ランキングは規約どおり同順位で出す。** 順位表と同じ共有順位を適用する。
   ただし実測すると同着は設計者の言う30人ではなく **270分ちょうどが81人** で、
   表示される行はすべて「1位」になる。1つのサイトに2つの順位規約を置かないことを優先した判断。
   **表示される全行が同順位になる以上、同着であること自体を一文で明示する**
   （例:「全試合フル出場の81人が同率1位」）。番号だけが並ぶと壊れて見えるため。
   節が進めば自然に解消する。

3. **名簿に存在しない43人は S11 では扱わない。** `npm run audit` の「注意」のまま運用する。
   多くは移籍直後で名簿が追いついていないだけの可能性が高く、フィードの更新で自然に解消する見込み。
   照合率（現在98.8%）を監査が毎回報告し続けるので、悪化すれば気づける。
